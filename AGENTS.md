# Repository Guidelines

## Project Overview

`erdtree` (binary `erd`) is a cross-platform, multithreaded filesystem and disk-usage tool. It combines parts of `du`, `tree`, `find`, `wc`, and `ls`: it respects `.gitignore` and hidden-file rules, reports physical/logical/block/word/line sizes, supports regex/glob filtering, several layouts, sorting, icons, `LS_COLORS`, and a Unix long view.

## Architecture & Data Flow

Single Cargo package, single binary. `src/main.rs` is the only orchestration point:

```mermaid
flowchart LR
  A[Context::try_init<br/>CLI + config merge] --> B[styles::init<br/>+ optional progress Indicator]
  B --> C[Tree::try_init<br/>walk::Walker, one sink per worker]
  C -->|columns per worker| D[Columns::merge<br/>struct of arrays]
  D --> E[tree::topo<br/>dedupe, sizes, sort, prune, filters]
  E --> F[render::write<br/>Rows per layout, parallel row chunks, ordered writer]
```

- **Context** (`src/context/`): `Context` is a clap derive struct that also carries derived runtime state (color policy); it holds raw option values only and does not depend on `walk`. `Context::try_init` returns the options and, beside them, the roots (the positional directories, `.` when none). The context is not changed after parsing, and column widths live on the `Tree` (`Tree::widths`). `Context::try_init` resolves `--threads 0` to `Context::num_threads` (the default count) once, so every phase reads `ctx.threads` as given. `args::compute_args` in `src/context/args.rs` merges config per argument using clap `ValueSource`: an explicit CLI value wins, config replaces defaults, and a value that is a default on both sides is left out of the merged args so it stays a default (`Context::threads_explicit` relies on that). Argument relations (`requires`, the `searching` group) are NOT declared on `Context`; `with_relations` in `args.rs` adds them and they are enforced once on the merged args, so add new relations there. TOML keys are converted to `--kebab-case` args (`src/context/config.rs`); `false` booleans are omitted. `--no-config` skips config; `-c NAME` selects a named TOML table and errors when no `.erdtree.toml` exists. `.erdtree.toml` is the only config file (the legacy rc format was removed and is ignored).
- **Walk** (`src/walk/`): `Walker` (configured by `walker()` in `src/tree/mod.rs` from the options and the canonical root; `src/walk/filter.rs` holds the hidden-entry policy `Hidden { Show, Hide, HideExcept }`, the `--exclude`/`--no-git` overrides (`filter::exclusions`), `Pattern` and the `EntryFilter` of `--include` without `--hidden`, `--pattern` and `--file-type`, all rooted at the canonical root) runs up to `--threads` workers: worker 0 runs on the calling thread, and another starts only when a worker has two or more local jobs and none is idle, or splits a listing, so a tree with nothing to share never spawns a thread. A worker lists a whole directory into a reusable `Listing` (`src/walk/listing/mod.rs`: one name arena with a NUL after each name, plus `d_type` per entry and, on Linux, the inode) with its own `Lister`, one per platform (`listing/linux.rs`, `listing/macos.rs`, `listing/other.rs`; `listing/fd.rs` holds the fd-relative opening shared by Linux and macOS), which owns its buffers; a queued `Job` carries the platform's `Access` (parent fd, follow, macOS bulk hint). The worker applies the ignore rules and the entry filter, and appends a record per kept entry to its own `Sink`. Records carry a platform-neutral `Stat` and `Kind` (`src/fs/stat.rs`), not `std::fs::Metadata`. Directories move between workers through a shared queue only when a worker is idle, and a directory with at least `SPLIT_MIN` (1024) entries is visited in blocks that idle workers take over (lazy binary splitting), so its records can live in several sinks (`--disk-usage line|word` split from 2 entries in blocks of 1, since each entry is a file read; `Tuning::reading_files`). Entries whose metadata fails are dropped with their contents and count as ignored (a `DT_DIR` entry is only stat'ed by the job that opens it, which counts it then). A queued job keeps its parent's directory fd open to open relative to it; `src/walk/fds.rs` budgets those fds from `RLIMIT_NOFILE`, and a job over budget opens by path, except paths of `fds::LONG_PATH` (`fs::PATH_MAX` - 96) bytes or more, which need the fd. Ignore files and `--follow` loop checks (device and inode of the walked directories) work relative to the fd, so they hold beyond `PATH_MAX`. Unless `--threads` is given (`Context::threads_explicit`, from clap `ValueSource`; a config `threads` counts), workers that block on I/O add workers: each worker adds its task wall time and, after 5 ms, compares it with its thread CPU time and voluntary context switches (`getrusage(RUSAGE_THREAD)`, Linux only, `src/walk/adaptive.rs`); a blocked window doubles the worker count up to `min(8 * threads, 64)` (`walk::max_threads` sets `Walker::max_threads`; on other systems, which cannot tell, it is `threads`, so `max_threads > 1` gates, the pool and the fd budget see the real count; tasks are timed only while the walk can still grow). Extra workers use the sinks after the first `threads` (the root is the first record of sink 0) and only walk; render and sort keep `threads`. Warm runs never trigger it, since preemption is not a voluntary switch. `src/walk/rules.rs` is adapted from the `ignore` crate's `dir.rs`, so ignore-file precedence matches `ignore::WalkParallel`; `tests/walk_oracle.rs` checks the walk against that walker, so keep both in step when changing either. A directory without ignore files shares its parent's `Rules` (not under `--follow`, and not for the root), and the global gitignore is built only once a repository is seen.
- **Linux walk** (`src/fs/at/mod.rs` shared with macOS, `src/fs/at/linux.rs`): a directory is opened with `openat` relative to its parent's fd (the job's `Access` holds an `Arc<DirFd>`; the soft `RLIMIT_NOFILE` is raised), read with raw `getdents64` (`d_type`, `statx` on `DT_UNKNOWN`), and each entry is stat'ed with `statx(dirfd, name)` asking only for the needed fields (`fstatat64` if `statx` is unavailable; `fs::probe::Probed` latches which system calls exist). The record of a directory that will be read is stored by the job that reads it, from `statx` of its open fd (`Me::Deferred`); `--traversal-depth` leaves keep the by-name stat, and a directory whose open fails is still recorded, without contents. Per-entry `readlinkat`, `listxattrat` (syscall 465, in `fs::xattr`, with a path-based fallback that fails beyond `PATH_MAX`), `openat` for `-d line`/`-d word` and the orphaned-link check go through `Record::{read_link, has_xattrs, open, target_exists}` using the directory fd, so no path longer than `PATH_MAX` fails a call; paths beyond it are now walked. Listings of at least 10000 entries on local file systems are visited in inode order. Windows keeps `std::fs::read_dir` behind the same `Lister`/`Listing` interface (`listing/other.rs`).
- **macOS walk** (`src/fs/bulk.rs`, `src/fs/at/mod.rs`, `src/fs/at/macos.rs`): the same fd-relative walk (`Arc<DirFd>`, budget, `openat`, `readlinkat`, `fstatat`, ignore files and `--follow` loop checks through the directory fd), but a directory is listed with `getattrlistbulk` (names plus metadata in one call; `ATTR_CMN_OBJTYPE` is always requested, since APFS otherwise takes a slow per-entry path; `ATTR_CMN_ERROR` follows the attribute sets) or with `readdir`, chosen per directory by `listing/macos.rs`: subdirectories use bulk when their parent recorded at least a third of its files, and very large directories (by the link count from `fstat` of the open fd, which `Lister::fill` reads itself unless the job already has it) use `readdir` with several workers so the `fstatat` calls can be shared. A directory's record always comes from `fstat` of its open fd (Cryptex graft roots report other metadata in bulk); a non-directory's bulk stat is trusted only on APFS, without errors, outside data vaults and when the mode agrees with the object type, otherwise `fstatat`. Paths of 1024 bytes or more behave as with path-based calls (`fs::fits_path_max`). The default thread count is the number of performance cores (`hw.perflevel0.physicalcpu`, `Context::num_threads`): more threads than that multiply kernel time on APFS. Directory `openat` dominates what is left (its kernel cost grows with depth). Walking `/dev/fd` shows erd's own held directory fds.
- **Columns** (`src/tree/columns.rs`): each record becomes one row of struct-of-arrays columns (names arena with `usize` end offsets (no size limit), depth, `Kind`, size). Data only some options need (mode for the long view and `--classify`, timestamps, long-view attributes) is collected only when `Probe` says so, and `LS_COLORS` styles are a `u16` index into a small table, resolved from the `Stat` by `src/styles/entry.rs` (a replica of `lscolors` 0.21 `indicator_for`, tested against `lscolors`); symlink targets and multiply-linked inodes are sparse lists. `Probe` is the one request of what the walk reads and collects: `tree::walker` takes its timestamp `fields` and, from `Probe::reads_files`, the walk `Tuning`. A worker's `Collector` holds the walk-only state (the `Probe`, the style resolver built from the colors `main` passes to `Tree::try_init`, the style cache, the read buffer, and the per-directory parent runs) next to its `Columns`, so the finished tree keeps only the columns. All filesystem I/O happens here, during the walk; later stages are CPU only. Keep it that way. `Columns::merge` keeps the largest sink in place and appends the others into exactly reserved space.
- **Assembly** (`src/tree/mod.rs`, `src/tree/topo.rs`, `src/tree/widths.rs`): `Tree::try_init(&Context, root, ..)` walks and assembles one root; `main` calls it once per root. `Columns::merge` concatenates the sinks and resolves parent references; for large trees groups of columns are copied by separate threads (the largest sink keeps its columns in place), which also spreads the page faults of the new memory, and it records the runs of equal parents for `Children`. `topo` holds the pure index algorithms (child lists, parent-first order by depth, pre-order, hard-link dedupe, size totals, prune, dirs-only, min-size) with Kani proofs. `assemble` relies on the `depth` column being the distance from the root (parent depth + 1): `aggregate` sums each directory's files over the child lists (shared out between threads) and then adds directories to their parents deepest first, a counting sort by depth is the parent-first order for `prune` and `hide_small` (built only when those run), and `preorder` always stops at `--level` (`Tree::order`; child lists are sorted only down to it). The filters (`--prune`, `--pattern`, `--dirs-only`, `--min-size`) only clear `alive` flags, and a shown node's parent is always shown, so the summary count (`file_count`), `is_stump` and the `--min-size` width scan read `alive` directly and cover every depth. The filters are derived once (`Filters`); `Children` and the `alive` flags live only during assembly, so after it a node's shown children are found from `order` (in pre-order, a node has one exactly when the next node is deeper). `Children` stores each parent's children as a range of `list`, built by copying the runs of equal parents (a directory is stored by the job that reads it, so its children form several runs). Child lists are sorted by packed integer keys (`Sorter` in `src/tree/node/cmp.rs`: directory class, size or time, 8-byte name prefix) with the full comparator only for equal keys, ties broken by name (`Ties::Name`; the global flat sort uses `Ties::Position`); long lists are sorted by all threads, and `src/tree/psort.rs` merges the sorted chunks with co-ranked pieces so that the last merge also uses all threads. `sort::Type::spec()` (`src/context/sort.rs`) gives what a sort orders by and its direction, in the frame of the sorted lists (the inverted/iflat order, top to bottom); keys, comparators and the timestamps `Probe` collects derive from it. A key must never order two nodes against the comparator; `keys_agree_with_comparators` checks every sort type and `--dir-order`. Hard-link dedupe sorts by `Inode::id` (`(dev, ino)`; the link count is data, not identity) and ranks group members without building paths (`Tree::path_cmp`). Column widths come from maxima over the columns (`widths.rs`), with one maximum per unit for `--human`; `assemble` builds `Tree::widths` once (`Widths::new`, one per root) from the `Stats` of a scan of every node (overlapping the sort of the child lists) or, with `--min-size`, of the shown nodes. `SizeFormat` (`Human(unit)`, `Bytes`, `Count`) is decided once from the context; the scan records it and `row::Size` reads it from `Widths::size_format`, which is `None` exactly when no scanned node has a size (no size column). The unit width is that of the longest unit name the format can show (`PrefixKind::names`), so the scan tracks only number widths. Owner and group names are resolved in their own step (`node::owners::Owners::resolve`, once per distinct id the scan found) before the widths, and `Node::owner_and_group` reads the same table. `Node` (`src/tree/node/`) is a `Copy` view (`&Tree`, index) used by sorting and rendering.
- **Disk usage** (`src/disk_usage/`): metric variants (logical, physical, block, line, word; `DiskUsage::is_bytes` and `reads_files` classify them) and unit prefixes. Physical size falls back to metadata length; Unix block counts are in `Stat::BLOCK_BYTES` (512) units. `units::PREFIXES` (5, bytes to tera) sizes every per-prefix table: unit names and bases (plus peta, which only `--min-size` accepts), the `--human` width buckets in `widths.rs`, and the unit colors (`Colors::du`).
- **Render** (`src/render/`): `render::write(&Tree, &Context, &Theme, out)` matches `ctx.layout` to build `Rows::Tree { inverted, glyphs }` or `Rows::Flat`. Tree prefixes come from ancestors through each worker's `prefix::Cursor`; with `--follow`, it tracks link-theme membership for symlinks and their descendants below the root. Flat rows combine `paths::DirPaths` with each name and prefetch scattered columns on x86-64. `row::RowFmt` is built once per tree from `Context`, the theme, `Tree::widths` and the merged style table; it decides columns and truncation, and shares precomputed painters across row workers. Rows append bytes directly, using `src/bytes.rs` for numbers and padding, UTF-8 names with a lossy fallback, and `ansi::truncate` (escape-preserving) when `--truncate` is given. Padding stays `{:>w$}`-identical (counts chars). `write_chunked` uses persistent workers claiming 4096-row chunks, recycled buffers and an ordered calling-thread writer; one thread or at most 8192 rows spawns nothing. The last tree is intentionally leaked by `main::run`. Unix long-view code and permission styling live in `src/render/long/`, with cached permission cells and hourly UTC offsets; `IsoStrict` and times outside 1970 to 2100 use chrono.
- **Styles** (`src/styles/`): `styles::init` builds the run's `&'static Theme` once and `main` passes it on (its `colors` to `Tree::try_init`, the theme to `render::write`); there is no global accessor. A theme holds tree and link branch glyphs plus `colors: Option<Colors>` (`LS_COLORS`, unit colors, placeholder, long-view styles); `colors.is_some()` is the only record of whether output is colored. Plain mode never parses `LS_COLORS`, and `prefetch_ls_colors` parses it on a helper thread during argument parsing. macOS `LSCOLORS` is not parsed. `Context::try_init` reads `NO_COLOR` into `Context::no_color_env` (only a non-empty value counts); `Context::no_color` decides the colour policy: `--color none` is plain, `force` colors (it wins over `NO_COLOR`), and `auto` colors on a terminal without `NO_COLOR`.

Style identities remain `columns::StyleIndex` (`u16`; `StyleIndex::new` is the one conversion, and past `u16::MAX` distinct styles it falls back to the default style) from collection through `Node::style`. `RowFmt` precomputes one `paint::Painter` per merged style-table entry and shares that table read-only across row workers; workers do not resolve or cache file styles. `styles::Glyphs` stores the prepainted branch bytes, borrowed by `prefix::Glyphs`. `render::paint` owns the shared optional-escape and placeholder-padding helpers and the fixed-color icon escapes (`push_fixed`); the permission colours and styling are private to `render::long`, and `Colors::link_arrow` supplies the symlink arrow/target style.

Pitfalls:
- Walk order and record order are not tree order. Only assembly sorts.
- A tree deeper than `PATH_MAX` is walked on Linux (everything is relative to directory fds); `tests/deep_path.rs` covers it. `tests/walk_threads.rs` and `walk::test` compare many threads with one on directories above the split threshold; the integration helper `run_cmd` uses `--threads 1`, so splitting is not covered by the other integration tests.
- `--level` limits display only; traversal and size totals still cover the full tree. `--traversal-depth` (same depth numbering, root = 0) limits the walk itself (`Walker::max_depth`), so sizes and counts then cover only traversed entries.
- `--dirs-only`, prune and `--min-size` clear `alive` flags after sizes are computed; column widths are computed over all nodes except after `--min-size`.
- An inode reached more than once counts once, towards the entry not reached through a symlink, then with the least path.

## Development Commands

Run commands inside the Nix dev shell (`flake.nix`, toolchain from `rust-toolchain.toml` via rust-overlay): `nix develop -c <cmd>`, or `nix develop` once.

```sh
cargo build                     # debug build
cargo run -- --threads 1 tests/data   # run erd on fixtures
cargo fmt --all -- --check      # CI gate; rustfmt.toml: match_block_trailing_comma = true
cargo clippy --all-targets --locked -- -D warnings   # CI gate
cargo test --locked             # CI gate (Linux, macOS, Windows)
cargo build --release --locked  # plain release build
dist plan                       # preview release artifacts (needs cargo-dist: nix shell nixpkgs#cargo-dist)
nix fmt flake.nix               # format flake.nix
nix flake check                 # crane checks: package build, clippy -D warnings, fmt, tests
nix build                       # crane release build (result/bin/erd); `nix run . -- <args>`
```

## Code Conventions & Common Patterns

- Rust edition 2024, MSRV 1.88 (`Cargo.toml`). Do not use std APIs newer than 1.88. Colors use `nu-ansi-term` (also enabled in `lscolors`); lazy statics use `std::sync::{OnceLock, LazyLock}`.
- Lints: `src/main.rs` enables `clippy::all`, `pedantic`, `nursery`, `cargo`, and more; CI denies all warnings. Fix lints instead of adding allows; a narrow `#[allow]` needs a comment with the reason (see `src/walk/mod.rs`).
- Errors: per-subsystem `thiserror` enums (`src/context/error.rs`, `src/context/config/error.rs`, `src/tree/error.rs`) with `From` conversions and `?`. Only `main` prints errors (stderr, once) and sets the exit code.
- Platform code: gate with `#[cfg(unix)]` / `#[cfg(windows)]` at module, field, and match-arm level (see `src/fs/`, `src/tree/columns.rs`). The fd-relative walk of Linux and macOS is `#[cfg(fd_walk)]`, a cfg `src/build.rs` sets for those two targets; write `fd_walk`, not `any(target_os = "linux", target_os = "macos")`. Windows builds on stable (hard-link identity via `windows-sys` in `src/fs/inode.rs`); CI builds and tests Windows, so keep both platforms compiling.
- Options are `Copy` + clap `ValueEnum` enums where practical. Global immutable state uses `OnceLock`; no other shared mutable state.
- New CLI flag: add it to `Context` (or a sub-struct) with a doc comment (clap uses it as help text), make sure TOML kebab/snake keys map to it, then update the literal `erd --help` output in `README.md` (Usage section).
- `CONTRIBUTING.md`: document what the code cannot say (constraints, invariants, external facts); no comments that restate the code; update README for user-visible changes; output changes need integration tests; open an issue before a PR. No commit-style rule is defined.

## Important Files

- `src/main.rs`: entry point, lint policy; builds one tree per root, then writes them with separators and the combined summary line; prints errors and sets the exit status.
- `src/context/mod.rs`: all CLI options and defaults (threads default and `--threads 0`: `Context::num_threads`, `available_parallelism` capped at the performance cores on macOS, fallback 3).
- `src/context/args.rs`: CLI/config reconciliation.
- `src/context/config.rs`: TOML discovery; inside an `erdtree` config directory the names `.erdtree.toml`, `erdtree.toml` and `config.toml` are tried in that order (`{…}` below). Unix order: `$ERDTREE_TOML_PATH`, `$XDG_CONFIG_HOME/erdtree/{…}`, `$XDG_CONFIG_HOME/.erdtree.toml`, `$HOME/.config/erdtree/{…}`, `$HOME/.erdtree.toml`. Windows: `$ERDTREE_TOML_PATH`, `%APPDATA%\erdtree\{…}`.
- `src/walk/mod.rs`, `src/tree/mod.rs`: walk and tree assembly.
- `.github/workflows/ci.yml`: fmt, clippy, tests on Linux/macOS/Windows, clippy for the release targets no other job builds (aarch64 and musl Linux, x86-64 macOS, plus i686 Linux; `cross` job), MSRV `cargo check` on 1.88.0, `cargo deny check` (`deny` job, config in `deny.toml`: advisories, licenses allowlist, bans warn on duplicates/wildcards, crates.io-only sources), aggregated into the `ci-pass` job (the required check for `master`; it reads the conclusion of every job of the run through the API, since `needs.*.result` missed cancelled matrix legs).
- `.github/workflows/nix.yml`: builds the x86_64-linux flake checks (`erdtree`, `clippy`, `fmt`, `test`) with the garret binary cache (`https://cache.jeiang.dev`) as a substituter. On pushes to `master` it also pushes every path built during the job to garret through `.ci/garret.sh` (`hook` writes the post-build hook, `watch` starts the client, `drain` pushes what is left; config in `.ci/garret.toml`), authenticated by GitHub OIDC (`id-token: write`, no secrets); the client is built from garret at `GARRET_CLIENT_REV`. Pushing fails unless the garret server allow-lists this repo and workflow. Push failures do not fail the job. Not part of `ci-pass`.
- `.github/workflows/release.yml`: generated by cargo-dist; never edit by hand. Config lives in `dist-workspace.toml` (targets, installers `shell`/`powershell`, sha256, attestations, native `ubuntu-24.04-arm` runners for aarch64 Linux, no crates.io publish) plus `[profile.dist]` in `Cargo.toml`. After changing config run `dist generate` (`dist generate --check` verifies it is current). `dist plan` runs on every PR; pushing a tag builds and publishes a GitHub Release.
- Release procedure: bump `version` in `Cargo.toml`, update `CHANGELOG.md`, merge, then push tag `vX.Y.Z` (any tag matching `**[0-9]+.[0-9]+.[0-9]+*` that matches the Cargo version; prerelease versions such as `v3.2.0-rc.1` publish as prereleases). The crate is not published to crates.io (that name is upstream's).
- `rust-toolchain.toml`: pinned dev/CI toolchain (1.99.0). Bump it deliberately and fix new lints in the same PR; `nix develop` and CI both follow it.
- `flake.nix` / `flake.lock`: dev shell, `packages.erdtree` (default), and `checks` (`erdtree`, `clippy`, `fmt`, `test`) built with crane. The crane source set is `commonCargoSources` plus `tests/`; add other non-Cargo files that builds or tests read to that fileset. The `test` check skips `styles::entry::test::setuid_bits_match_ls_colors` and the `setuid_bit::` goldens in `tests/color.rs`, since the Nix sandbox refuses setuid/setgid bits; keep such cases in tests of their own so the rest runs. Update with `nix flake update`.
- `CHANGELOG.md`: SemVer release notes.

## Runtime/Tooling Preferences

- Cargo; no workspace, no Cargo features, no profile overrides. CI installs the `rust-toolchain.toml` version with `rustup toolchain install`; the `msrv` job overrides it with `RUSTUP_TOOLCHAIN: 1.88.0`. When raising `rust-version` in `Cargo.toml`, update that job.
- macOS start-up: the binary must link only `libSystem` (check `otool -L target/release/erd`); dyld loading frameworks cost about 1.5 ms per run. `src/build.rs` passes `-Wl,-dead_strip_dylibs` on macOS, and chrono is built without its `clock` feature on macOS (iana-time-zone links CoreFoundation): the long view's local time zone comes from `tz-rs` (`src/render/long/zone.rs`, following chrono's `TZ` rules; `zones_match_chrono` compares them). Do not enable a dependency feature that links a framework.
- Windows builds on stable Rust and runs in CI (clippy and tests). `tests/data` is marked `-text` in `.gitattributes` so fixture sizes stay byte-exact on Windows.
- Dependabot (`.github/dependabot.yml`) opens weekly PRs for `cargo` and `github-actions`. Run `cargo deny check` locally with `nix develop -c nix shell nixpkgs#cargo-deny -c cargo deny check`; new dependency licenses must be added to `deny.toml` deliberately.
- `Cargo.lock` is committed; releases build with `--locked`. Do not hand-edit it.

## Testing & QA

- Standard `#[test]` harness. No `assert_cmd` or snapshot crate. Dev deps: `indoc`, `strip-ansi-escapes`, `tempfile`.
- Integration tests call `tests/utils/mod.rs::run_cmd(&[...])`, which runs the test build of `erd` (`CARGO_BIN_EXE_erd`) with `--threads 1 --disk-usage logical --sort name --no-config <args>`, strips ANSI, trims, and panics with stderr on non-zero exit. Assert the full rendered tree against an `indoc!` string.
- Unit tests sit beside the code, for example `src/context/config/test.rs`, `src/fs/permissions/test.rs` (Unix), `src/disk_usage/file_size/line_count.rs`.
- Run one test:
  ```sh
  cargo test --test sort sort_name -- --exact
  cargo test disk_usage::file_size::line_count::tests::lines_of_a_file -- --exact
  ```
- Adding a CLI test: new or existing `tests/<area>.rs` with `mod utils;`, use `tests/data/` fixtures, keep ordering explicit, use logical sizes (physical sizes differ by filesystem), gate Unix-only cases with `#[cfg(unix)]` (see `tests/symlink.rs`), use `tempfile::TempDir` for custom setups. Colored output is pinned byte for byte with `run_cmd_raw` and `-C force` (`tests/color.rs`, `tests/follow_level.rs`).
- Fixture caveats: changing anything in `tests/data/` changes expected sizes and trees across many tests.
- Formal verification: `mod spec` in `src/tree/topo.rs` states the topology properties; sorting lives in `tree::psort`, node indices in `tree::id`, and shared scoped work in `src/par.rs`. `mod test` checks the topology properties exhaustively for every tree of up to 6 nodes and every root position (part of `cargo test`). `mod proofs` (only under `cfg(kani)`) checks trees of 1 to 3 nodes, one harness per property and size (`tree::topo::proofs::prune::n3`, `...::dedupe::n3_m2`, `...::hide_small::n3_k2`). `aggregate` takes no order: it sums files over child lists, then propagates directory totals deepest first. `prune` accepts any parent-first order of all nodes (`spec::is_parent_first_order`); `hide_small` accepts any connected alive set and a parent-first order of it (`spec::is_parent_first_order_of`), filtered after pruning and `--dirs-only`. The pre-order spec asserts that `preorder` produces such orders. `preorder` and `last_alive_child` have only 1-node Kani smoke harnesses because their output length is symbolic (8 GB at 2 nodes); exhaustive tests cover them. Kani trees use a depth-witness generator equivalent to `spec::is_tree`. Keep Kani inputs at concrete lengths and spec code free of loops over symbolic-length data (use `ancestors` bitsets), which exhaust CBMC's memory. Run `cargo kani -j 4 --output-format=terse` (about 1.5 minutes; install: `cargo install --locked kani-verifier && cargo kani setup`; not in the dev shell). Changes to topology algorithms need their specs updated.
